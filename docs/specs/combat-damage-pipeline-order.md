# Damage pipeline order

**Description**

An attack passes through checks and damage calculations before it changes the target's life. Life stealing, cold, poison, item effects and reactions each occur at a particular point. Their order matters because later steps use the damage and random choices left by earlier steps.

## 1. Scope


This spec defines the ordered stages that turn one connected (or attempted) melee attack into final resource changes on the defender, and the RNG draw order of that path: the hit-result hand-off (which result bits gate which later stages), the damage-record build (physical roll, crit/deadly doubling, elemental fields, leech inputs, status-length terms, conversion, the monster damage double), the difficulty/PvP scale placement, total and predicted-lethal flag, the apply step (gates, events, clamp, leech, absorb heal, life subtraction, mana/stamina burn, status appliers, death flag), the post-apply steps of the queued path (durability draw counts, events 7/3, reflection, reaction) and every dispatch point where other code may draw. The per-type mitigation arithmetic (flat reduction, resistance, pierce, absorb, bypass) belongs to [combat-damage-mitigation](combat-damage-mitigation.md); the to-hit roll and block/avoid to [combat-shield-block-and-avoidance](combat-shield-block-and-avoidance.md); leech arithmetic to [combat-leech-and-drain](combat-leech-and-drain.md); the status appliers to [combat-status-application](combat-status-application.md); scale percentages and hostility to [combat-pvp-damage-and-kill-credit](combat-pvp-damage-and-kill-credit.md); durability-loss arithmetic to [item-durability-loss](item-durability-loss.md); item-event callbacks to [combat-item-event-triggers-and-procs](combat-item-event-triggers-and-procs.md); the reaction to [combat-hit-recovery](combat-hit-recovery.md). Out of scope: Crushing Blow, Open Wounds, thorns attribution, missile-unit damage rolls, the skill handlers reached through states (DPO-R33) and monster modifiers (DPO-R30), which are only placed in the order here.

## 2. Trigger and ownership

D2Game on the server owns the path. A player attack frame event runs skill do dispatch; `Skills.srvdofunc = 1` selects the basic-attack operation (SCD-R06, SCD-R09a, SCD-R14a). The path target is the defender. Missing target or self-target returns failure before this path. An early alternate branch is excluded from this supplied-path contract (DPO-Q19); monster frame-event roots and upstream hit-callback callers remain DPO-Q20. The companion records every original source link.

The basic attack zeroes a damage record, obtains hit result, sets already-built, runs the before-build state pass, builds with weapon mode 0 and ratio 128, runs the after-build state pass, then enters queued build completion. Build runs on hit and miss. An eligible hit runs scale/mitigation and predicted lethal; either hit or miss then enqueues. An intermediate route or the direct route reaches queued apply. Optional-route eligibility and side effects remain DPO-Q19.

Queued apply finds and copies the matching entry, tests reach, applies on hit, adds marks and durability on the pre-apply hit test, dispatches events 7/3, reflects on a surviving hit, reacts on hit or miss, then removes matching entries. These operations occur synchronously within the attack's server frame. Deferred operations include regeneration at frame+1, freeze event type 2 and timed-state expiration.

The separate hit callback returns before build on miss. Other queued callers build only when eligible and not already built. Missile contact supplies its own record and requests scale/mitigation inside apply. DPO-R08c/d distinguish the direct caller profiles and their number of scale runs. Client resource/reaction messages are outside this boundary; no message identity is established.

## 3. Inputs and data

Notation consumes NRF-R01/R02 for seeds and draws, NRF-R05 for `mulDiv`, NRF-R06a for signed truncation/wrapping, NRF-R08a for raw 8.8, RLI-R02/RLI-R03 for stat/state reads and the stat-write dependency for writes. `Stat(unit,id)` is a layer-0 read; `SetStat` is a layer-0 write; `HasState` is a state test. `draw` and `drawAlt` give identical results; `drawInRange(m)` uses lower bound 0. `stepMod(unit,m)` steps once then takes unsigned low-word remainder by m. Ordinary arithmetic is signed 32-bit with wrapping products/sums and truncation toward zero unless an unsigned test is stated.

## 4. Rules (execution order)

Shared local operations use i32 inputs, wrapping additions/products and signed truncation. These names are illustrative:

```
rangeRoll(unit,base,mn,mx,minPct,maxPct):
    if mx <= 0: return max(0,base)
    low = mn + mulDiv(minPct,mn,100)
    high = mx + mulDiv(maxPct,mx,100)
    value = base + low
    if high > low: value += drawAlt(unit,high-low)
    return max(0,value)
elementRoll(unit,maxId,minId,masteryId,prior):
    mx = Stat(unit,maxId) << 8
    if mx < 8: return max(0,prior)
    mn = Stat(unit,minId) << 8
    mastery = 0 if masteryId absent else Stat(unit,masteryId)
    return rangeRoll(unit,prior,mn,mx,mastery,mastery)
scale(value,ratio):
    return value if ratio == 128 else truncatingDivide(wrapped32(value*ratio),128)
scaleAlways(value,ratio):
    return truncatingDivide(wrapped32(value*ratio),128)
```

Build ratio is u8. Zero normalizes to 128 at entry, before every use including burn. Only the elemental fields (DPO-R04a) skip the multiplication at ratio 128; the drain, poison, length and burn terms use `scaleAlways`, so at ratio 128 a term with magnitude at least 2^24 wraps.

**DPO-R01** **Hit result and avoidance hand-off.**

- **DPO-R01a** [verified in 1.13c code (static)]. Start result 0. Both units must be player/monster and supplied hostility must succeed, else return 0. A running player defender pre-sets hit. Reach must succeed, else return 0, even with hit pre-set. Unless hit was pre-set, obtain the supplied to-hit result using attacker, defender, progressive-to-hit and zero extra term; a nonzero return sets hit, and a zero return leaves hit clear, so the avoidance call below is skipped. With hit set, obtain avoidance value b: each set b mask maps independently (2 to 256, 4 to 128, 16 to 32768, 1 to 16, OR-ed together); any nonzero b clears hit. Result mask 16 clears hit again. Surviving hit without defender state 54 sets result 4. Scale/mitigation and prediction require hit and no result mask in 0x8380. Queued apply and state passes require hit. Basic attack builds on hit and miss; the separate hit callback returns before building on miss. Queued completion skips building when already-built. This hand-off draws nothing itself; supplied hit/avoidance operations own their draws.
- **DPO-R01b** [asm-only]. Reach allowance k is 3 for monster attacker, else 1. Nonzero progressive-to-hit s subtracts weapon-style reach+s from k. Supplied reach tests special monster defender classes 258/261 using defender reach+8>distance; otherwise limit=attacker weapon-style reach+k+1, allowing distance<=0, rejecting distance>limit, then requiring collision test with mask 0x804 to return 0. Before queued apply k is plain 3/1 without the s subtraction. Distance/collision and player weapon-style producer integration remain DPO-Q23.

**DPO-R02** **Physical range.**

- **DPO-R02a** [verified in 1.13c code (static)]. Every build, on hit and miss, first normalizes ratio and then ORs build-marker flag 32 into the record flags before any roll. Physical-supplied skips roll, ratio scaling and crit, preserving physical unscaled; every other build stage still runs. Otherwise with supplied endpoints/percentages, the first build draw is rangeRoll on attacker, one draw iff adjusted high>low. Store physical. Ratio 128 keeps it; otherwise use mulDiv(ratio, value,128), in that argument order, consuming NRF-R05. With value>0x100000 its applicable branch is (value/128)*ratio; ratio<=255 excludes the large-first-argument branch. This ratio scaling precedes crit doubling (DPO-R03a doubles the scaled value).
- **DPO-R02b** [asm-only]. With weapon present, selector 2 uses stats 23/24, otherwise 21/22; without weapon use the unarmed 21/22 pair, first raising a minimum below 1 to 1 and a maximum below 2 to 2. Add stat 111 to endpoints and shift left 8. Minimum<1 becomes 256; maximum<=minimum becomes minimum+256. Percent starts at physicalPercent+stat 25. With weapon add signed strength*weaponStrengthFactor/100, dexterity*weaponDexterityFactor/100 for nonzero factors (each factor sign-extended from 16 bits) and supplied mastery percent; without weapon add strength. Floor this shared percent at -90 (values <= -90 become -90) before stats 18/17 are added; the endpoint sums are not floored. Call rangeRoll with prior physical as base, percent+stat 18 for minimum and percent+stat 17 for maximum, then DPO-R02a scaling. Weapon/factor/selector/mastery integration is DPO-Q27.

**DPO-R03** **Exclusive crit/deadly doubling.**

- **DPO-R03a** [verified in 1.13c code (static)]. After physical roll, try weapon chance only with weapon mode 0 and weapon present, then stat 337, then stat 141. Each positive chance costs one attacker drawInRange(100); signed roll<chance succeeds. First success shifts physical left once, sets result 8192 and stops. Nonpositive chances draw nothing. No elemental doubling here. Physical-supplied skips every crit source.
- **DPO-R03b** [asm-only]. Weapon identity and weapon chance producer remain DPO-Q27. The ordered supplied-chance operation above does not verify their production.

**DPO-R04** **Elemental fields.**

- **DPO-R04a** [verified in 1.13c code (static)]. In order fire, lightning, cold, magic: write scale(elementRoll(attacker, maxId, minId, mastery, prior), ratio). Each positive shifted maximum with adjusted high>low takes one attacker draw; otherwise keep max(0, prior), no draw, still ratio-scale the returned value. Prior field is the roll base.
- **DPO-R04b** [verified in 1.13c code (static)]. Maximum/minimum/mastery ids are fire 49/48/329, lightning 51/50/330, cold 55/54/331, magic 53/52/357. Read mastery only with positive maximum and use it for both endpoint percentages.

**DPO-R05** **Drain inputs** [verified in 1.13c code (static)]. Hireling classifier returns 0 for null/non-monster; monster class 271 gives 1,338 gives 2,359 gives 3,560/561 give 4, otherwise 0 (GDF-R08). Regular monster (no MonStats row is read for the drains) rolls life 61/60, mana 63/62, stamina 65/64 in order, skipping flags 4/8/16: field+=scaleAlways(elementRoll(attacker, maxId, minId, absent, field), ratio). Prior field counts twice. Player/hireling draws nothing: lifeDrain+=stat 60 unless flag 4; manaDrain+=stat 62 unless flag 8; no stamina addition. Only on this player/hireling path, three independent tests follow: nonzero stat 103 ORs flag 256, nonzero stat 104 ORs flag 512 and nonzero stat 106 ORs flag 1024, so several flags can be set together. Other attacker types add nothing.

**DPO-R06** **Poison and status lengths.**

- **DPO-R06a** [verified in 1.13c code (static)]. After drains, poisonMagnitude=scaleAlways(rangeRoll(attacker, prior, stat 57, stat 58, m, m), ratio), with raw endpoints. m=stat 332 only when stat 58>0, otherwise 0. One attacker draw iff maximum>0 and adjusted high>low.
- **DPO-R06b** [verified in 1.13c code (static)]. Nonzero poisonMagnitude (the value DPO-R06a stored after its ratio scaling, so a roll that scales to 0 skips this length step): positive stat 101 adds to poisonLength; otherwise poisonLength=poisonLength+stat 59 and, only in that else branch, when stat 326>1 the whole sum is divided by stat 326 with signed truncation. Poison length is not ratio-scaled. Positive cold (the value DPO-R04a left, before conversion and the monster double) adds scaleAlways(stat 56, ratio) to coldLength. Zero incoming stunLength adds scaleAlways(stat 66, ratio); nonzero stunLength stays. Burn follows DPO-R21.

**DPO-R07** **Conversion** [verified in 1.13c code (static)]. After build event 3, before monster double, nonzero conversionType computes converted=mulDiv(conversionPercent, physical,100), with that argument order, then physical=max(0, physical-converted). Type 10 takes attacker draw(5) (also when conversionPercent is 0) and continues as type result+1 (1..5), applying that type's handling below. Types 1/2/3 add converted to fire/lightning/magic. Type 4 adds to cold and raises coldLength to at least 50. Type 5 adds converted/8 (signed, truncated toward zero) to poisonMagnitude and raises poisonLength to at least 50. Types 6..10 add nothing further. Type 11 adds to fire and raises burnLength to at least 50; type 12 adds to cold and raises freezeLength to at least 50. Other nonzero types only subtract physical. Type 0 does nothing.

**DPO-R08** **Scaling and entry profiles.**

- **DPO-R08a** [verified in 1.13c code (static)]. With supplied P!=100, visit section 3's twelve entries in order. Positive scale-enabled values become mulDiv(P, value,100), preserving NRF-R05 argument and branch order. Nonpositive fields and the three lengths stay unchanged. P=100 skips scaling. Numeric P selection remains DPO-R08b.
- **DPO-R08b** [asm-only]. P is the factor PVP-R02a selects (17, 25, the difficulty hireling/boss percent, 200/400 or 100 in that contract's order); this spec consumes that contract and does not restate its predicates. The production of PVP's scale condition remains PVP-R02b (DPO-Q01). Before selection, physical/magic flat reductions are stats 34/35 shifted 8; each positive reduction with positive flatReductionScale becomes mulDiv(flatReductionScale, reduction,1024) (DMI-R02, which owns use of these inputs).
- **DPO-R08c** [verified in 1.13c code (static)]. Eligible queued completion runs the scale/mitigation stage after build, before prediction/enqueue; later queued apply requests no second run. Apply with scale request true runs it after gates, before apply events. Entry profiles: *queued* (above); *callback* (missile contact or hit callback applies with scale request true, one run); *direct-then-flagged* (the caller itself runs scale/mitigation on its record, then applies with scale request true: two runs); *direct-then-unflagged* (caller runs it itself, then applies with scale request false: one run); *unscaled local profiles A and B* (caller applies a locally built record with scale request false without running it: zero runs). Original caller identities are in the companion; callers supply one of these entry profiles.
- **DPO-R08d** [verified in 1.13c code (static)]. Queued eligible hit runs once, miss zero; either still enqueues. Enqueue accepts only player/monster defenders, records game, attacker/defender identities and damage, and pushes at attacker queue head. Missile/flagged callbacks request one apply-time run and do not also enqueue. Direct-then-flagged runs twice, direct-then-unflagged once, unscaled local profiles A/B zero. Allocation dependency integration remains DPO-Q30.

**DPO-R09** **Pre-strip event 11** [verified in 1.13c code (static)]. After scaling, unconditionally including P=100, dispatch event 11 on defender list with other=attacker and the shared record. Callbacks see scaled, unstripped fields. Placement adds no draw and ignores dispatcher result; IEP-R07 owns traversal.

**DPO-R10** **Length strip** [verified in 1.13c code (static)]. Runs after event 11 (DPO-R09) and before the mitigation loop (DPO-R11). If coldLength>0 or freezeLength>0, nonzero defender stat 153 zeros both; otherwise nonzero stat 118 halves both with signed truncation, including a negative partner. Positive poisonLength becomes 0 with state 133. Positive burnLength becomes 0 with state 131. No draw.

**DPO-R11** **Mitigation dispatch** [verified in 1.13c code (static)]. Start bypass 0. Undead and demon are DMI-R04's class tests (undead: MonStats lUndead or hUndead; demon: MonStats demon). Monster defender: undead+flag 256 or demon+flag 512 sets 1; only neither undead nor demon tests flag 1024. Null/non-monster defender uses flag 1024. Visit the twelve entries in section 3 order. At a monster-only entry, end loop unless attacker is a regular monster. Each visited field consumes DMI's per-entry mitigation with bypass and supplied flat reductions. No local draw; event 11 callbacks own theirs.

**DPO-R12** **Total and predicted lethal.**

- **DPO-R12a** [verified in 1.13c code (static)]. At the end of each scale/mitigation run (and only there; an ineligible queued completion leaves the record's total unchanged), store wrapping total=physical+fire+lightning+magic+cold+poisonMagnitude, plus lifeDrain only for regular monster attacker. Eligible queued completion independently recomputes the six-field sum plus lifeDrain for any monster-type attacker, including hireling; this prediction neither reads nor writes stored total. Set result 2 if signed (prediction&~255)>(defender life&~255); otherwise leave result unchanged (a result 2 already present is not cleared). Equality does not pre-set lethal. Then enqueue, even when hit was ineligible for scaling/prediction.
- **DPO-R12b** [unresolved]. Poison enters immediate total and also supplies the poison status operation. Combined gameplay interpretation remains DPO-Q02; DPO-R12a's supplied-field sum remains available.

**DPO-R13** **Queue consumption and apply gates.**

- **DPO-R13a** [verified in 1.13c code (static)]. Find the first entry, walking from the queue head, matching attacker/defender type/id; none returns without effect. Copy that entry's whole damage record (every field); later matching entries are not read. Removal, wherever this rule removes, deletes every matching entry and keeps non-matching entries in their order. Supplied reach uses allowance 3 for monster attacker, else 1; failure removes all matching entries and returns without events/apply. Miss skips apply/marks/durability and goes to 7/3. On hit, player/monster attacker in mode 0 returns before apply, retaining queue. Repeat this mode test after 7/3 if hit still set; failure returns before reflection/reaction/removal. Only on hit, after the first mode test, replace the copied flags with 32 and apply with scale request false; a miss keeps the copied flags for events 7/3 and the reaction.

  Apply gates in order: (1) failed supplied hostility without flag 4096 clears result 1/2 and returns; absent defender room does the same even with override. (2) In supplied town room only monster attacker with inTown continues; others, including a monster attacker whose MonStats row is missing, clear only result 2 and return. (3) Monster defender without killable returns unchanged. (4) Null/invalid defender, non-player/non-monster, mode 0, monster mode 12 or player mode 17 returns unchanged. (5) Store last attacker type/id and presence; null attacker zeros both and clears presence. (6) Requested scale/mitigation runs here. (7) Only with result 32 clear and hit set (for both forms below), apply with scale request false dispatches attacker 5 then defender 1; apply with scale request true requires record flags 32, then dispatches attacker 6 unless record flags 128, then defender 2 (no dispatch when record flags 32 is clear). "Unflagged" and "flagged" apply name the scale-request argument, not the record flags. Each dispatch supplies other=opposite unit and shared record. Events precede clamp; ignore dispatcher return. Supplied-predicate ordering/effects are available; missing integration remains DPO-Q23/DPO-Q30.
- **DPO-R13b** [asm-only]. Hostility/town meanings consume PVP-R05a/PVP-R06; unread subpaths remain DPO-Q30. Override bypasses hostility alone.

**DPO-R14** **Clamp** [verified in 1.13c code (static)]. After gate 7, DPO-R14 through DPO-R19 run whether or not hit is set (only DPO-R30 tests hit). Set physical=min(physical, defender raw life), signed. Keep total unchanged. No draw.

**DPO-R15** **Leech hand-off** [verified in 1.13c code (static)]. Invoke LSE with clamped, mitigated physical. ## 6. Branches and edge cases

- Attacker type: a regular monster (type 1, hireling predicate 0) rolls drain inputs (DPO-R05), adds `lifeDrain` to the total (DPO-R12a), is mitigated for all 12 table entries (DPO-R11) and may double all six damage fields (DPO-R22); a hireling (classes of GDF-R08) is treated like a player by DPO-R05 and DPO-R12a's stored total, but like a monster by the predicted-lethal recomputation and by the monster double (DPO-R22); a player attacker adds leech stats unrolled (DPO-R05) and pays the mana-burn quirk (DPO-R18); other types add nothing and dispatch no build event 3.
- Defender type: only types 0 and 1 reach the hit result (DPO-R01a) and the queue (DPO-R08d); a monster defender needs `killable` (DPO-R13a step 3) and is the only one that receives the stun draw (DPO-R27), the regen reschedule (DPO-R19c) and the pre-roll adjustments (DPO-R31); a player defender in `Run` has bit 0 pre-set (DPO-R01a).
- Hit versus miss on the basic attack: the build and all its draws run either way; the scale, predicted-lethal bit, apply, durability, reflection and the state handlers run only on a hit; the enqueue, events 7/3, the reaction and the dequeue run either way (DPO-R01a, DPO-R08d, DPO-R23, DPO-R26). On the hit-callback path a miss ends before the build.
- Hit-in flag (`flags & 1`) skips the physical roll and all crit draws (DPO-R02a, DPO-R03a), not the other build draws (DPO-R21a); flag 0x1000 allows the apply when the hostility check fails (DPO-R13a), except on the queued path, where queued apply operation overwrites the flags with 0x20 first.
- Scale/mitigation placement (DPO-R08c): at build time on the queued path, inside the apply on the flag-1 paths, twice on direct-then-flagged profile, never on unscaled local profile A and the self-apply of unscaled local profile B (DPO-R08d).
- Crit applies to physical only (DPO-R03a); conversion runs on the doubled value (DPO-R07); the monster double applies after conversion to all six damage fields (DPO-R22).
- Zero and negative inputs: a max stat `<= 0` makes no draw; an elemental field becomes `max(0, previous)` scaled (DPO-R04a), while a regular-monster drain field adds `scaleAlways(max(0, previous), ratio)` to itself, so a positive prior doubles at ratio 128 (DPO-R05); `rangeRoll` never returns a negative value; `physical` after conversion is floored at 0 (DPO-R07); the strip halves negatives toward zero (DPO-R10); a total `<= 0` leaves life unchanged (DPO-R17); manaDrain and staminaDrain amounts `<= 0` are ignored (DPO-R18); `burnMagnitude` gains at least 2 per build from 0 (DPO-R21b).
- Overflow: the physical ratio scaling, the P scaling and conversion use `mulDiv` (NRF-R05); the elemental ratio scaling (`scale`) and the drain, poison, length and burn terms (`scaleAlways`, DPO-R05, R06a, R06b, R21b) multiply with 32-bit wrapping before the truncating divide by 128, and `scaleAlways` does so even at ratio 128; the sums of DPO-R12a wrap in 32 bits; the crit doubling is a plain shift.
- Missile versus melee: weapon actions and the hit callback use the same build; missile-unit contact does not (it rolls on the missile's seed, missile roll operation; [skill-assassin-blade-sentinel-and-fury](skill-assassin-blade-sentinel-and-fury.md) BSF-R07), then runs DPO-R22 on the owner before the apply with flag 1; durability, events 7/3, reflection and the reaction of the queued path are not run by the missile apply.
- Difficulty: enters only through `P` (DPO-R08b: the hireling-vs-monster case reads `DifficultyLevelsRecord.HireableBossDamagePercent` of the game's difficulty; every other listed `P` is a constant) and the appliers' divisors (CSA-R05, CSA-R08); classic versus expansion only through the throwable durability rule (DPO-R24a).
- Missing data: a monster class at or beyond the MonStats count makes DPO-R22 draw nothing, DPO-R31's class tests false and DPO-R13a step 3 fail; a null stat list makes every `Stat` read 0 (RLI-R03) and max-life read return 0 (so the absorb cap is 0).
- Neighbors: [combat-knockback](combat-knockback.md) and [combat-hit-recovery](combat-hit-recovery.md) consume `result` and `hitClass` after DPO-R26.
